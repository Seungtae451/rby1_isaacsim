# 로컬 영상 재구성와 RBY1 Model A 데이터 수집 설계

상태: **승인 대기. 구현·배포 완료 문서가 아님.** 기존 `reconstruct.py` 등은 Superpowers 적용 전 작성한 미검증 초안이다.

## 목적과 우선순위

회사 환경 영상을 외부 서비스에 전송하지 않고 GPU로 재구성하고, Isaac Sim에서 RBY1 Model A를 배치한다. 이후 Quest 3 컨트롤러와 상체 골격으로 양팔·그리퍼를 조작하여 로컬 LeRobot 데이터셋을 수집한다.

**2026-10-27 사용자 지정: Docker는 영상에서 Isaac Sim용 환경 자산을 생성하는 재구성 작업에만 사용한다.** 컨테이너의 입력은 로컬 영상이며 출력은 NuRec USDZ와 재구성 메타데이터·로그다. 이 과정의 3DGUT 장면 학습은 재구성에 포함한다. Isaac Sim 실행·환경 로딩·물리 설정·RBY1 배치·Quest 서버·teleoperation·LeRobot 저장/변환·로봇 정책 학습은 Docker에 포함하지 않고 로컬 호스트에서 실행한다. 기존의 슈퍼컴 로봇 정책 학습용 Docker 제안도 이 지시로 제외한다.

사용자가 명시한 첫 번째 검증은 **실제 영상을 받은 뒤 로컬에서 재구성하고 Isaac Sim에 로딩하는 것**이다. 영상이 없거나 카메라·장비가 준비되지 않은 상태에서 전체 기능이 검증됐다고 보고하지 않는다.

## 확인한 현재 상태

- 작업 폴더는 구현이 없는 상태였으며 `.git` 폴더도 유효한 Git 저장소가 아니었다. 원격 저장소 주소는 주어지지 않았다.
- 현재 PC: Ubuntu 계열 Linux, Python 3.10, Docker, RTX 5080 16GB 두 장, 드라이버 580.95.05. 두 GPU에서 다른 작업이 실행 중이며 이를 종료하지 않는다.
- 현재 PATH에는 ffmpeg와 COLMAP이 없고 RBY1/3DGRUT Docker 이미지도 없다. 대형 이미지 빌드 및 GPU 재구성은 아직 실행하지 않았다.
- `../humanoid_teleoperation`에는 Quest WebXR 상체 관절 8개, 손목·팔꿈치 자세 retargeting, 로컬 HTTPS 서버 및 LeRobot v2.1 변환 코드가 있다.
- `../quest_robot_isaac`에는 F14의 컨트롤러 입력·그리퍼·클러치·TLS 코드가 있다. 기존 두 프로젝트는 수정하지 않는다.
- 기존 상체 입력은 실험적 `XRFrame.body` API에 의존한다. Quest 3 Browser에서 상체가 실제 제공되는지는 아직 확인하지 못했다.
- 공개 저장소만 내려받았고 버전은 `external.lock.json`에 고정했다. 사용자 영상은 아직 제공되지 않았으며 읽거나 업로드한 영상이 없다.

## 접근 방식

채택 제안은 NVIDIA가 문서화한 **단안 카메라 COLMAP → 3DGUT → NuRec USDZ → Isaac Sim** 경로다. 사용자가 지정한 NuRec과 일반 영상 입력을 만족하는 가장 직접적인 방법이다. 선택 주체는 아직 사용자 승인이 아닌 구현자 제안이다.

대안은 다음과 같다.

1. 스테레오 기반 재구성: 깊이와 미터 단위 정렬에 유리하지만 추가 센서·촬영 방식이 필요하다. 이번 일반 영상 입력의 기본 경로로 쓰지 않는다.
2. AV용 NuRec 컨테이너/NCore 경로: 차량 센서·보조 데이터 구성을 요구하므로 실내 단안 영상의 첫 검증에 불필요하다.

단안 영상은 절대 크기와 중력 방향을 보장하지 않는다. **실측 길이 하나 이상 및 바닥 정렬 검증**이 필요하다. 화질·겹침·시차가 부족한 영상은 자동 복구를 약속하지 않고 SfM 검증 단계에서 중단한다.

## 보안 경계

- 준비 단계: 공개 코드·패키지·컨테이너·필요 모델 가중치만 승인된 인터넷 연결 PC에서 내려받는다. 회사 영상과 데이터셋 디렉터리를 빌드에 마운트하지 않는다.
- 실행 단계: 영상 재구성 컨테이너만 `network=none`으로 실행한다. offline 환경 변수는 보조 장치이며 네트워크 차단을 대신하지 않는다.
- Isaac Sim·데이터 변환·로봇 정책 학습은 로컬 호스트에서 실행한다. 외부 송신 차단은 호스트 방화벽/회사 망 정책으로 적용하고 검증한다. 코드의 offline 설정만으로 외부 송신 차단을 보장하지 않는다.
- Quest HTTPS 입력 서버도 로컬 호스트에서 실행한다. 회사 내부 Quest 연결만 허용하며 TLS·접속 토큰·단일 조작자·메시지 크기 제한·스키마 검증을 사용한다. 입력은 호스트 내 로컬 통신으로 전달한다. Quest 서버는 영상·학습 데이터셋을 웹으로 제공하지 않는다.
- Quest로는 웹 클라이언트와 최소 연결 응답만 제공하는 것을 기본으로 제안한다. 로봇 영상 스트리밍은 첫 버전에 포함하지 않는다.
- `network=host`, 공개 TURN/STUN, Cloudflare/ngrok, CDN, Hugging Face 업로드, W&B 온라인 로깅은 실행 경로에서 사용하지 않는다.
- Quest OS 자체의 외부 통신은 서버 코드로 통제할 수 없다. 회사가 관리하는 WAN 차단 AP/VLAN과 호스트의 통신 정책이 필요하다. Docker 격리가 호스트·헤드셋 전체의 보안을 보장한다고 주장하지 않는다.
- 영상은 채팅 첨부 대신 **회사 PC의 로컬 경로**로 제공한다. 프레임·영상·개인 데이터 내용을 외부 도구 입력으로 전달하지 않는다. 로컬 프로그램의 상태·수치로 검증한다.
- 코드만 Git에 포함한다. 영상·재구성 결과·데이터셋·인증서·키·모델 가중치·캐시는 Git과 Docker 빌드 컨텍스트에서 제외한다.
- 외부 반출이 금지된 데이터의 슈퍼컴 전송은 회사 내부의 승인된 장비·절차를 전제로 한다. Git 원격에는 코드를 게시하는 작업과 데이터 이동을 분리한다.

## 첫 구현: 영상에서 Isaac Sim까지

1. `--video <local path> --job <new local directory>` 한 번으로 입력한다. 기존 job은 덮어쓰지 않는다.
2. ffmpeg로 초당 2프레임, 최대 폭 1600의 초기 검증용 프레임을 추출한다. 회전 촬영만 하지 않고 이동하며 여러 시점과 충분한 겹침을 확보한다. 실제 영상 결과를 보고 필요한 경우 조정한다.
3. GPU SIFT와 순차 매칭을 사용하는 COLMAP으로 카메라·희소 지도를 구한다. 하나의 모델에 최소 30장, 전체 추출 프레임의 80% 이상이 등록되지 않으면 실패로 보고한다. 이는 초기 품질 게이트이며 완전한 재구성 품질 보증은 아니다.
4. 고정한 3DGRUT commit의 실제 옵션에 맞춰 3DGUT MCMC를 실행한다. 현재 소스는 문서의 예전 `export_usdz` 대신 `export_usd.enabled=true`, `export_usd.format=nurec`를 사용한다.
5. 결과 `scene.usdz`, 입력 해시, 프레임 등록 통계, 로그를 로컬 job에 보관한다. 실패 산출물도 남겨 디버깅한다. 외부 가중치가 필요하면 사전에 이미지에 캐시하며 런타임 다운로드 실패를 우회하지 않는다.
6. 여기까지의 USDZ 생성이 Docker의 종료 지점이다. 이후 로컬 호스트의 Isaac Sim에서 NuRec asset을 로컬 참조로 로딩하고 렌더한다. 초기에는 별도 영상 없이도 로봇만 생성하는 smoke 검증을 수행한다.
7. 실측 기준 scale/rotation/translation을 설정하고 바닥과 크기를 확인한다. 정렬 검증 전에도 preview는 허용하지만 teleoperation 데이터 수집은 차단한다.
8. Gaussian은 시각 표현이다. 실제 충돌은 별도의 바닥·작업대·벽 proxy로 구성한다. 조작할 물체는 별도 동적 rigid body로 만든다. 영상만으로 자동으로 정확한 물리와 가려진 물체를 복원하는 기능은 첫 범위에 없다.

16GB 두 장은 단일 32GB GPU처럼 동작하지 않는다. 작은 장면을 한 GPU에서 먼저 검증하며 대형 장면 메모리 요구량은 실제 영상으로 확인한다. AV NuRec의 하드웨어 요구사항을 단안 3DGUT 경로에 그대로 적용하지 않는다.

## RBY1 Model A와 Quest

- 시뮬레이션 모델: 공식 `rby1-sim-isaac`의 `assets/model_v_1_2_a.usd`와 `rb_gripper`를 사용한다.
- 기구학 모델: 공식 `rby1-sdk/models/rby1a/urdf/model_v1.2.urdf`를 사용한다. USD와 URDF 관절 이름·축·영점 일치를 검증한다. 이미 제공된 공식 USD를 매번 URDF에서 재변환하지 않는다.
- 공식 PD 제어·토크 제한·그리퍼 장착 처리를 재사용한다. 첫 버전은 바퀴 정지, 몸통 기본 자세 고정, 양팔과 그리퍼 조작이다. 이동·몸통 직접 제어는 사용자 추가 요구 시 범위를 확장한다.
- Quest grip/squeeze를 누르는 동안만 조작한다. 클러치 시작 때 손목·시선 기준을 캡처하여 목표가 갑자기 뛰지 않게 한다. trigger는 각 그리퍼 닫힘 정도에 연결한다.
- 컨트롤러 손목 목표와 상체의 어깨·팔꿈치·손목 방향 및 팔꿈치 굽힘을 7축 팔 IK에 반영한다. 인간과 로봇 링크 길이가 다르므로 절대 골격 위치를 그대로 복사하지 않는다. 관절 한계와 속도 제한을 적용한다.
- 타임아웃·역순 입력·세션 변경·비유한 값·추적 손실은 조작 해제로 처리한다. 복귀 시 클러치를 다시 눌러 기준을 잡아야 한다.
- 상체 API가 없는데 팔꿈치를 추적한다고 표시하지 않는다. 브라우저에서 제공되지 않으면 Meta 네이티브 OpenXR `XR_FB_body_tracking`/Movement SDK 송신 앱이 필요하다. 이 경우 공식 샘플을 기반으로 로컬 송신 어댑터를 만들며, APK 빌드·설치·실기 검증이 추가 작업이다. 임의 팔꿈치 추정으로 요구사항을 대체하지 않는다.
- IK는 기구학적 자세 추종이다. 공식 모델의 자기 충돌 제한과 실제 충돌 회피 미구현을 표시하며 실물 로봇에는 연결하지 않는다.

## 데이터와 학습 배포

- 기존 OpenPI 환경과 호환되는 공식 LeRobot **v2.1** 형식을 초기 기준으로 제안한다. 현재 로컬의 `lerobot 0.1.0` 구현과 버전을 확인하고 고정한다. 최신 v3와 혼용하지 않는다.
- 의미를 고정한 `observation.state`, `action`, `observation.images.front`, task, episode/frame/timestamp 메타데이터를 공식 writer로 작성한다.
- 양팔 관절 14개와 좌우 그리퍼 2개를 포함한 16차원 절대 목표 action을 제안한다. state도 같은 순서를 사용하며 단위는 rad 및 정규화 그리퍼 닫힘이다. 고정된 몸통과 이동 상태, 원본 Quest 골격, 장면 정렬과 IK 설정은 로컬 부가 메타데이터에 보존한다.
- 프레임은 시뮬레이션 시간 기준 고정 주기로 RGB·state·적용 action을 함께 수집한다. 추적 중단은 유효한 시연으로 조용히 저장하지 않는다.
- 원본 episode는 임시 디렉터리에 저장하고 명시적 저장 시 원자적으로 확정한다. 실패한 변환은 원본을 보존하며 기존 데이터셋을 덮어쓰지 않는다.
- 로봇 정책 학습은 Docker에 포함하지 않는다. 로컬 또는 회사 내부 슈퍼컴 호스트에서 로컬 데이터와 사전 준비된 모델/패키지만 읽고 결과를 로컬 경로에 저장한다. 먼저 작은 ACT 등 로컬 학습 smoke 경로를 검증하며 대형 π0.5 학습은 슈퍼컴 환경·체크포인트·학습 방식이 확인된 후 설정한다. 사용자에게 특정 학습 알고리즘이 이미 합의됐다고 간주하지 않는다.
- 영상 재구성 이미지만 인터넷 가능한 준비 단계에서 빌드하고 `docker save/load`로 폐쇄망에 전달한다. 나머지 실행 환경은 호스트 설치 절차로 준비한다. 실행 이미지·공개 소스 commit·실험 설정을 기록한다. 모든 라이선스와 Isaac Sim 사용 조건은 유지한다.

## 변경 범위

이 저장소의 Python 패키지, 호스트 실행 스크립트, Quest 정적 웹 클라이언트, JSON 설정, 영상 재구성 전용 Dockerfile/실행 스크립트, 테스트, 한국어 사용 문서에 변경이 필요하다. Docker 이미지에는 RBY1 자산·Quest·LeRobot·로봇 정책 학습 코드를 넣지 않는다. 기존 `.dockerignore`는 미검증 초안이며 구현 시 재구성 전용 허용 목록으로 정리한다. `external/`에는 고정한 공개 저장소만 두고 코드와 자산의 출처·라이선스를 기록한다. 기존 humanoid/F14 프로젝트·시연 데이터·실행 프로세스는 건드리지 않는다.

## 검증 및 완료 기준

1. 네트워크가 없는 컨테이너에서 작은 샘플의 프레임 추출·COLMAP·USDZ 생성이 실제로 완료된다.
2. 잘못된 입력·실패 재실행·여러 SfM 모델·등록률 실패에서 원본과 기존 산출물이 보존된다.
3. Isaac Sim에서 로컬 NuRec scene과 Model A/그리퍼가 로딩·렌더되고 원격 asset 없이 동작한다.
4. 알려진 길이와 바닥 정렬 및 proxy 충돌을 실제 화면과 로컬 측정으로 확인한다.
5. 입력 검증·만료·재연결·클러치·IK 관절/속도 한계에 테스트가 있다.
6. Quest 3에서 실제 상체 관절과 컨트롤러 입력을 동시에 확인하고 팔꿈치 추종과 그리퍼를 검증한다.
7. 작은 실제 시연을 저장하고 공식 LeRobot reader로 재로드하여 프레임 수·차원·시각·동영상의 일치를 확인한다.
8. 영상 재구성 컨테이너의 `network=none` 설정과 실행 명령을 확인한다. 시뮬레이션·Quest·데이터 저장·로봇 정책 학습이 컨테이너에 포함되지 않았는지 확인하고, 호스트 외부 송신 차단 상태에서 각각의 smoke 결과를 남긴다. 헤드셋 WAN 차단은 회사 네트워크 관리 범위임을 구분한다.
9. 원격 주소가 지정되면 코드만 Git에 올린다. 주소가 없는 상태에서 임의 GitHub 저장소를 만들거나 데이터를 게시하지 않는다.

## 아직 필요한 현장 검증 정보

영상은 로컬 파일 경로로 제공되어야 하며 실제 길이 기준과 촬영 범위가 필요하다. Quest 상체 API 노출, 회사 네트워크에서 HTTPS 접속 허용 여부, 슈퍼컴의 GPU/VRAM·스케줄러·호스트 Python/CUDA 환경, Git 원격 주소는 실제 연결 단계에서 확인한다. 재구성을 슈퍼컴에서 실행한다면 그 작업에 한해 Docker 사용 가능 여부를 확인한다. 이 정보가 없어도 독립적인 코드·테스트·오프라인 배포 준비는 진행할 수 있다.
